# Leaphouse Remote — телефон

Android-приложение (`uz.electro.remote`, Kotlin + Compose). Ходит **только** в
Electro Backend; ни endpoints вендора, ни ключей машины в нём нет.

## Как оно устроено

```
Settings            SharedPreferences: адрес сервера, токен, выбранная машина
  ↓
CloudClient         Retrofit; при смене адреса пересоздаётся, при смене токена нет
  ↓
CarRepository       единственная точка доступа к машине; разбирает отказы
  ↓
CarViewModel        состояние, опрос, оптимистичные переключатели, события
  ↓
экраны              вход → привязка → подключение → машина/карта/климат/управление
```

Экраны идут воротами: без входа — только вход, регистрация и восстановление
пароля; без привязанной машины — только сканер QR; дальше экран подключения,
и лишь потом управление. Регистрация доступа к машине не даёт — его открывает
физический доступ к экрану головы, где показан одноразовый код.

## Решения, о которых стоит знать

**Путь к машине один — сервер.** Прямой канал на голову по `:8777` убран: он
требовал общей сети с машиной и включённого на голове adb, а в боевой машине
adb выключают сразу после установки. Один путь заодно снимает разнобой: набор
команд и скорость опроса перестали зависеть от того, каким каналом повезло
пройти.

**Адрес сервера не зашит в сборку.** Правится в приложении (Настройки →
«Адрес сервера»); умолчание и подмена устаревших адресов — в `data/Settings.kt`.
Зашитый на сборке адрес означал бы, что смена сервера — это переустановка APK
у всех.

**Сессия живёт в `SharedPreferences` и пишется `commit()`, а не `apply()`.**
`apply()` возвращается сразу и дописывает файл потом; если процесс умрёт раньше
(обновление APK, «Остановить» в настройках Android), человек молча окажется
разлогинен — а сессия живёт неделю.

**Охрана и замки — разные вещи.** `security_state` показывается отдельно от
`doors`. Снятая с охраны машина с запертыми дверьми раньше показывалась как
«на охране». Машина на охране с отпертыми дверьми выделяется красным: это то
самое небезопасное состояние, которое сервер компенсирует блокировкой.

**Состояние переключателей — из `raw`.** Сервер отдаёт сырые сигналы головы
(`cabin_temp`, `outside_temp`, `temp_l`, `fan`, `trunk`, …) специально для
телефона, потерявшего прямой канал. Без них экраны показывали бы только эхо
собственных нажатий. Имена сигналов — из `CarStateReader` агента на голове.

**Отказ показывается словами.** Непрошедшую команду сервер отдаёт кодом 5xx;
`CarRepository.reasonOf()` достаёт `error`/`detail` из тела, чтобы на экране
было «пробуждалка не ответила за 15 с», а не «HTTP 502».

**Машина выбирается по модели.** Из парка берётся C16: у C11 и C01 другой
набор команд, и «первая из списка» означала бы отправку команд в машину,
которая их не понимает.

**Кнопка «Выключить всё» не переключается по состоянию.** Машина отдаёт `ac=0`
и при работающем обдуве, поэтому подпись «Включить климат» появлялась на уже
работающем климате. Кнопка гасит весь климат списком `Cmd.allOff()`: обогревы,
сиденья, массаж, кондиционер и обдув последним — он общий для системы, и
выключенный первым успел бы включиться обратно.

**SMS-побудки нет.** Запасной канал через SIM в T-BOX убран вместе с
разрешением `SEND_SMS`: обратной связи у него нет вовсе, «отправлено» означало
лишь «отдано оператору», и сломанная пробуждалка годами подменялась бы
сообщениями, которых никто не проверяет.

## Чего приложение не покажет

Двери по отдельности и капот: в карте сигналов головы их нет, есть только
общий замок. Поля в `CarState` оставлены под будущую прошивку.

## Сборка

```bash
./gradlew assembleRelease
```

Адрес сервера задавать не нужно — он в настройках приложения. Release
подписывается отладочным ключом намеренно: приложение раздают файлом, и свой
ключ означал бы, что обновление не встанет поверх установленных копий. Отпечаток
можно вписать в `-PexpectedSig=…`, тогда включится `SignatureGuard`.

Шкала климата: 18 — это `LO`, 32 — `HI`, между ними градусы.
